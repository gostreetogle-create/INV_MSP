# Паспорт: обозначения (артикулы) деталей/модулей/изделий — PDM

**Статус: подтверждённый стандарт компании.** Применяется ко всем будущим проектам, не только к
текущему изделию в `Inventor_MSP`. Один пункт остаётся открытым — см. «Не уточнено» внизу.

## Формат

```
0000.0000.0000
Изделие.Модуль.Деталь
```

Три группы **ровно по 4 цифры** (`0000`–`9999`, с ведущими нулями), разделённые точками.
**Букв XXXX/YYYY/ZZZZ в реальных обозначениях не существует** — это были условные обозначения
для примера в таблице ниже. На практике везде просто цифры.

## Как читать обозначение (позиционная логика)

Значение каждой позиции определяется тем, ноль там или нет:

- **1-я группа** ненулевая → запись принадлежит изделию с этим номером.
- **2-я группа** ненулевая → запись принадлежит модулю с этим номером.
- **3-я группа** — номер самой детали; если `0000` — запись это не деталь, а сам
  модуль/изделие (т.е. вся строка описывает модуль или изделие целиком, а не деталь внутри
  него).
- Если группа перед деталью/модулем вся из нулей — значит деталь/модуль **общая**, ни к чему
  конкретному не привязана (каталожная/базовая).

## Правила из скриншота

| Обозначение | Что это | Сленг |
|---|---|---|
| `XXXX.0000.0000` | изделие | городок |
| `XXXX.YYYY.0000` | модуль YYYY в составе изделия XXXX | городковый модуль |
| `XXXX.YYYY.ZZZZ` | деталь ZZZZ в составе модуля YYYY, который в составе изделия XXXX | деталь городкового модуля |
| `XXXX.0000.YYYY` | деталь YYYY, входящая в изделие XXXX напрямую (не через модуль), либо в несколько модулей изделия XXXX | городковая деталь |
| `0000.XXXX.0000` | модуль, входящий в несколько модулей/изделий | каталожный / базовый / стандартный модуль |
| `0000.XXXX.YYYY` | деталь YYYY, входящая в модуль XXXX (из строки выше) | — |
| `0000.0000.XXXX` | деталь, входящая в несколько модулей и/или изделий | базовая / каталожная / стандартная деталь |

## Имя файла

**Только код обозначения**, без читаемого названия рядом. Пример: `1000.0002.0004.ipt`.

## Выдача номеров — ручной ввод

Номера привязаны к категориям через отдельный каталог компании, но прямого программного
доступа к нему пока нет, и он обновляется "в моменте" (кто-то может уже занять номер). Поэтому
**в приложении номер вводится вручную** пользователем при создании детали/модуля/изделия —
никакой автогенерации/автоинкремента следующего свободного номера пока не делаем. Если позже
появится доступ к каталогу — вернуться к этому и добавить проверку занятости номера.

## На будущее (не реализовано, черновая идея)

Пока каталог/PDM недоступны программно, приложение может **локально** вести таблицу уже
использованных номеров (простой список/JSON: обозначение → тип → дата создания), чтобы хотя бы
в рамках этого инструмента не выдать один и тот же номер дважды. В перспективе — синхронизация с
реальной PDM (сверка при создании нового изделия/модуля/детали, импорт занятых номеров оттуда).
Решение не принято, требует уточнения, когда появится доступ к PDM для тестирования.

## Не уточнено — обсудим позже

Пользователь упомянул, что в некоторых обозначениях (похоже, для **сборочных схем**) встречаются
ещё и **буквы** — точный формат и назначение пока не готовы сформулировать, обещали уточнить
отдельно, когда соберут больше информации. Не закладывать в логику, пока не подтверждено.

## Куда это подключается в приложении

Планируется: при создании детали/модуля/изделия через «Пульт» — поле ручного ввода обозначения
(`0000.0000.0000`) с проверкой формата (ровно 3 группы по 4 цифры), которое становится именем
файла при сохранении. Пока не реализовано — ждёт связки с реальным сценарием создания файлов
(см. `INVENTOR_NOTES.md`, раздел «Эскизы / экструзия», где уже отработано создание `.ipt` через
COM).
